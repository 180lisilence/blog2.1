📁 四、五大项目方向复盘

▶ 本章重点：五条主线并行，博客系统与 DSH 生态是投入最深的两块。

📰 4.1 博客系统：从静态页到全门禁 Web 应用

博客是贯穿全年的主线项目，仓库演进路线：1.0fabuban → myself-blog → blog2.0 → blog2.1（当前线上版本）。blog2.1 是这套系统的完全体：Node.js 后端 + 全站登录门禁 + CSP 严格策略 + Sentinel 审计后台（3100 端口独立服务）。这个项目让我完整走了一遍 Web 全栈：MySQL 设计、会话管理、bcrypt 密码哈希、Express 中间件、PM2 部署、CSP 报告-上线双阶段切换。

同期还写了 xiaoxiaoxiao 双端日记工作台，走的是另一条路：纯前端、localStorage 存储、不登录、不联网。和 blog2.1 形成对比——一个是"重安全、重权限"的门户，一个是"轻量、本地优先"的个人工具。

🧩 4.2 DSH 插件生态：从一个悬浮球到一个列表

DSH 是我下半年投入最多的方向。围绕它的仓库形成了一个小生态：自有插件 dsh-floating-ball（悬浮球唤起）、dsh-election-chajian（内容选择）；Fork 学习 dsh-desktop、dsh-pojia-mode、DSH-Plugin、deepseek-harness、DSHA；社区建设 awesome-dsh-plugin，并在 11 月 16 日向上游提交 PR #15790。

DSH 的设计理念 "Everything is a Plugin" 影响了我对 AI 工具的认知——AI 不应该是一个封闭的聊天窗口，而应该是一个可扩展的运行环境。

🎮 4.3 游戏修改器：0.2 → 0.3 的重构

游戏修改器是另一条持续投入的线：woldvein_trainer（主修改器，已从 0.2 迭代到 0.3）、woldvein_injector、woldvein0.2（已归档）、woldveiHouse、smooth_game（2.0 大重构）、critical-game、gamehub、Game-Cheats-Manager。

这条线让我完整走了一遍 Windows 内存读写流程：CE 找静态偏移、指针扫描定位多级指针链、Python 写原型、再考虑 C++ 重写核心。0.3 版本做了一次彻底的模块拆分——内存读写、注入、UI、配置各自独立。

⛏️ 4.4 Minecraft 开服与运维

MC 是我长期的爱好，也是运维经验的主要来源：MSL（WPF 开服器 Fork）、my-world-monitor-tool（自写监控：进程存活、日志读取、崩溃自动重启）。开服教会我的不是怎么装插件，而是怎么让服务长期稳定在线：JVM 参数、G1 GC、FRP 断线重连、日志滚动、崩溃自动拉起、定时备份。这些经验后来直接迁移到博客服务器运维上。

🔍 4.5 逆向与底层

逆向方向的仓库相对零散：rea + rea-tool-myself、card-unlock-master（Smali 练习）、3D-model-construction（C++）、personal-information-anliaysis。目前还在学习期，Smali 入门、IDA 静态分析、CE 动态调试三件套正在一个个啃。

📝 七、踩过的坑与方法论

▶ 本章重点：本地优先、双远程备份、安全先行、稳定优先、备份常态化——五条工作流原则。
  1. 本地优先，服务器只跑不写。博客项目所有改动先在本地完成，测试通过再上传服务器，最后推 GitHub + Gitee 双远程。
  2. 双远程备份。GitHub + Gitee 同时推，互为异地容灾。两个仓库提交哈希永远一致。
  3. CSP 严格模式是好事。inline script/style 全外链化，收窄 XSS 攻击面。
  4. 工具优先稳定，功能其次。修改器 0.3 花大力气拆模块，就是为了以后加功能不动核心。
  5. 备份是流程不是附加项。博客数据库每天 dump，MC 存档每天打包，代码 Git 双远程。

352 次贡献，55 个仓库，12 种语言，从一个静态 HTML 页面写到一套全门禁博客系统、一个 DSH 插件生态、几个游戏修改器、一套 MC 开服监控。这一年没有什么惊天动地的开源大作，但每一行代码都是为了解决自己真实遇到的问题而写。

写工具这件事最有意思的地方在于：你今天花半小时写的小脚本，明天可能就变成你每天都会打开一次的日常工具；你今天 Fork 来学习的一个开源项目，半年后可能变成你自己生态的一部分。
