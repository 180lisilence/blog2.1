# 台账字段 · 分级口径 · 变体兼容 · 红线纪律

## 1. 七套台账与职责

| 文件 | 职责 | 填写时机 |
|---|---|---|
| `identity.txt` | 一行式身份卡：N/package/versionName/app_name/source/note | 阶段 0 首建，阶段 1 补全 |
| `方向.txt` | 样本定位 + a/b/c 三条后续方向，与待办 ④ 一一对应 | 阶段 0 |
| `analysis.md` | 静态分析报告七节：一句话用途/核心功能/使用方法/技术栈/后端网络/关键发现/分析深度 | 阶段 1–2 |
| `待办进度.md` | 六小节闭环进度：①概况与工具链复核 ②已完成+证据 ③未执行项+前置+复现命令 ④方向 a/b/c 现状 ⑤脚本/产物清单 ⑥可修改点清单 | 全程回填 |
| `可修改点清单.md` | 穷尽改动点登记，A/B/C/D 分级 + 计数汇总 + 阻塞清单 | 阶段 3 |
| `项目记忆.md` | 本包长期事实：身份/资产/关键类/静态结论/兜底链/方向/分级计数/产物索引/红线 | 各轮回填 |
| `交接.md` | 当前断点：一句话状态/已完成可复算/断点 P1-P3/未执行前置/恢复顺序/复现命令/风险 | 阶段性收口 |

## 2. 身份字段（identity.txt）

```
N=<样本编号>
package=<包名>
versionName=<版本名>
app_name=<应用名>
source=<APK 文件名或来源目录>
note=<一句话备注：引擎/类型/渠道/状态>
```

- versionCode、minSdk/targetSdk、ABI、入口 Activity、Application、体积从 badging/Manifest 实读；读不到写"未确认"。
- 多变体逐变体登记，不合并。

## 3. 证据标签口径

包内统一一套，禁止两套混用：

- **【事实】**：命令/文件实测可复算（附证据路径）。
- **【推断】**：交叉推断，待动态或下一轮确认。
- **【缺口】**：未取得证据；未执行/未反汇编/未运行均归此。

变体（部分历史包用）：已验证 / 观察(假设) / 未运行；与包内既有台账保持一致即可。

## 4. 可修改点 A/B/C/D 分级（风险档口径，原文定义）

| 档位 | 含义 |
|---|---|
| A | 静态可直接 patch：Java/smali 常量、Manifest 节点、assets 明文数据、偏好默认值可在反编译工程内直接改，重打包后行为可见变化；改后可静态校验。 |
| B | 仅能改 UI 展示：文案、布局、图标、颜色、视图显隐、枚举显示名等展示层改动，不触及校验/网络/授权逻辑，不改变功能判定与授权结果。 |
| C | 受服务端/远程保护，本地不可绕过：状态判定、鉴权、云同步、远程下发变量均以后端返回为准；本地无静态可替代点，改 URL/UI 不能伪造授权或内容信任。 |
| D | 需 native 层 / 脱壳 / Lua / 加密容器解包：主保护 dex 方法体、so、daemon、VMP、壳完整性校验；本轮无反汇编与动态环境，仅登记阻塞原因与前置条件，不闭环、不编造改法。 |

每条必须含：定位（文件:行/类/so 符号/资产路径）、现状（实读）、可改法或阻塞原因、影响面与风险。

### 变体语义辨析（不要混用编号）

- **区域字母法**：A Manifest / B 壳 smali / C 受保护 DEX / D assets / E native so / F 资源字符串——字母是区域归类，**不是风险档**，须在清单 §0 注明。
- **通道总览法**：配置 JSON / smali 补丁 / 源码补丁 / res 资源 / assets 资源 / native so 六通道 + 不可改边界。
- **系列编号法**：前缀按链路归属（如 G/C/R、M/F/S/N/J/K 等系列），落地状态二分"已可写回 / 候选待复核 / 不可纯静态落地"。

## 5. 两套进度骨架兼容

- **主线六小节**（待办进度.md）：①概况 ②已完成+证据 ③未执行项 ④方向 a/b/c ⑤脚本/产物 ⑥可修改点。
- **批次变体**（待办进展.md）：按方向键组织 `<样本号>-a/-b/-c` + 跨项已完成 + 产物清单 + 未执行项；第三轮后可追加 ⑦ 深化小节。

## 6. 红线纪律（强制）

1. 不主动探测/扫描/请求任何样本后端域名、IP、卡密端点；网络结论只来自静态提取。
2. 被标记为受限的后端域名及其子域禁止任何攻击/扫描/探测/渗透/爆破/压测/漏洞利用动作。
3. 被标记为红线的样本仅结构归档，不排还原/绕过/联调任务。
4. 原始 APK、原始样本、历史产物只读；不删不改不移动。
5. 凭证（token、私钥、签名库口令、密钥）只登记存在，不读取、不转写、不进对外摘要。
6. 动态项（装机/运行/抓包/frida/脱壳/patch）未实测前标"未动态验证"；未执行命令不写执行结果。
7. 静态通过 ≠ 运行通过；编译/签名/反编译成功不代表功能生效。
8. 在线对战/授权/付费/结算由服务端校验，本地改点只影响客户端表现、本地 PVE 与界面显示。

## 7. 缺口登记写法

未执行项必须写全四要素：原因、前置条件、可复现命令、当前状态；阻塞清单与 D/C 级编号逐条对应。工具/依赖缺失时记缺口与替代路径，不跳过编造结果。
