bat 脚本相关（关键，勿再犯）

  1. 换行必须是 CRLF！Write 工具写 LF，cmd 解析 LF bat 报 "The syntax of the command is incorrect"。修法：ReadAllText + -replace "`r?`n","`r`n" + WriteAllText
  2. 内容用纯英文，避免中文！cmd 读取 bat 的代码页=启动时的 OEM 代码页（中文系统 GBK），与编辑环境（UTF-8）不一致导致中文路径乱码。中文文件名只能在命令行层处理，不能在 bat 内容里写中文路径 → 用英文别名 bat
  3. 不要 chcp 65001（会把 GBK 内容读乱）
  4. echo 行禁括号（if(...) 块内括号被拆开当命令执行）
  5. timeout 在输入重定向下报 "Input redirection is not supported" 并退出 → 改用 ping -n 3 127.0.0.1 >nul
  6. 交互菜单（set /p）在无真实控制台的自动化环境行为异常，无法自动验证；但语法标准、菜单显示正常、真实双击正常
  7. 测试 bat：杀干净 cmd 进程再测；用 cmd /c 'bat < 输入文件' 或 cmd 内部管道

已验证死路（不要重复尝试）

  • project5 自制 Steam API 代理 DLL 测试无效（游戏 exe 不加载它，Steam 集成走 XGSDK 内部通道）
  • B 方案 DLL 劫持代理 version.dll 未实施，被散文件方案取代
  • 方案 C v7 PEB 遍历动态获取 LoadLibraryA 的 shellcode 有 bug（启动后立即崩溃）
  • 方案 C shellcode 使用绝对地址会因 ASLR 崩溃（v4/v5 早期版本）
  • 方案 C 代码洞穴在 .text virtual_size 之外不会被映射到内存（v5 版本崩溃原因）
  • DLL 在游戏早期直接初始化会崩溃（需要延迟初始化）
  • version.dll Hook 版（含 INT3/Inline Hook）物理引擎初始化失败
  • B 方案外部内存已弃
  • 早期错误结论"pakv4 重打包不可行"已推翻（实际 ZSTD 无加密，重打包可行）
  • 早期错误结论"Lua 脚本加密存储"已推翻（实际 ZSTD 压缩）
