A 方案：DLL 注入 + Lua Hook（project1，主力，v17 路径自适应版）

原理三层：DLL 注入（远程 LoadLibraryA）→ IAT Hook（lua_pcall 导入槽）→ 捕获 lua_State L → 执行 Lua 代码。

  • Lua 版本 5.1；lua_pcall 导出偏移 = Lua5X64.dll base + 0x25E0
  • 资源读写：g_camp.m_tbSource[ID]=数量；用 ModifySourceValue 才正确同步 UI；人口必须用 g_camp:ModifyPopulation API
  • 命令后门：lua_cmd.txt 写任意 Lua 代码，DLL 每 50ms 轮询消费后删除
  • 当前 DLL：trainer_v15.dll（v17 路径自适应版，59.8KB）

v17 全部路径自适应化（2026-09-03，用户要求"跟随变化"）

  • 不再写死任何绝对路径，整个文件夹可任意移动 / 改名 / 拷贝
  • DLL 加载时用 GetModuleFileName 自动识别自身所在目录
  • 首次 hook 时设置 Lua 全局 _TRAINER_DIR = 工作目录（正斜杠）
  • C 层路径用 ANSI(CP_ACP) 编码，中文目录也能用
  • Launcher.exe（2865KB 静态编译）支持相对 DllPath + 默认 v15

ImGui 关键技巧 & 线程安全

  • 窗口大小必须设 ImVec2(360,430)（早期）/ ImVec2(620,900)（v13 大面板），否则游戏限制只能显示 2 行
  • InputText 需要 KLString 缓冲 + 第 3 参数 maxLen=128
  • 运行时 SetWindowSize(ImVec2(620,1000)) 会导致游戏崩溃！改默认尺寸要改代码里的 SetNextWindowSize 再重载 lua
  • 绘制 hook 必须用 g_LUiPageManager.GameDraw，不能用猜的全局 _G.GameDrawUI
  • 线程安全（v9 起修复崩溃）：之前热键线程（外部线程）直接调用 Lua API，与游戏主线程并发操作同一个 Lua 状态导致崩溃；修复：热键线程只"收命令入队"，真正执行 Lua 放到游戏主线程的 my_lua_pcall 钩子里

C 方案：二进制补丁 exe（project3，最终成功，v9 IAT 寻址）

目标：直接修改游戏 exe 入口点，插入 shellcode 加载修改器 DLL，然后执行原指令跳回。

  • 最终版本：v9（IAT 寻址获取 LoadLibraryA，完全不受 ASLR 影响）
  • 测试结果：游戏正常启动，运行 15 秒+ 无崩溃，DLL 成功加载，延迟初始化正常，IAT Hook 成功，热键线程启动

关键技术突破（按解决顺序）

  • ASLR 问题：游戏启用 DYNAMIC_BASE，shellcode 不能用绝对地址 → 用相对跳转（E8/E9）
  • 代码洞穴映射问题：代码洞穴在 .text 节区 virtual_size 之外不被映射 → 修改 virtual_size 从 0x60BE8E 改为 0x60C000
  • LoadLibraryA 地址获取：不能硬编码（ASLR）、PEB 遍历太复杂 → 通过游戏导入表（IAT）条目获取，IAT 条目 RVA=0x0060D258，完全不受 ASLR 影响
  • DLL 加载时机：DLL 在游戏入口点加载时核心子系统未初始化 → 延迟初始化（Sleep3 秒 → 检测 Lua5X64.dll → Sleep2 秒 → Hook）

PE 结构关键参数

  • 入口点 RVA=0x0049D28C，文件偏移=0x0049C68C，ImageBase=0x140000000
  • 代码洞穴 RVA=0x0060CE90，文件偏移=0x0060C290，大小 368 字节
  • 原入口点指令：48 83 EC 28（sub rsp,0x28）+ E8 DF 08 00 00（call）
  • 原 call 目标 VA=0x000000014049DB74，跳回地址 VA=0x000000014049D295（入口点+9）
  • LoadLibraryA IAT 条目 RVA=0x0060D258；.text 节区 VSize=0x60BE8E（原）→ 0x60C000（修改后）

版本迭代历史

  • v1-v2：int 3 断点验证补丁机制
  • v3：正式版本，崩溃（跳回地址 + ASLR + 代码洞穴）
  • v4：空转测试，崩溃（代码洞穴未映射）
  • v5：修复 ASLR（相对跳转），仍崩溃（代码洞穴未映射）
  • v6：修复代码洞穴映射（修改 virtual_size），空转成功运行 60 秒+
  • v7：PEB 遍历获取 LoadLibraryA，崩溃（shellcode 有 bug）
  • v8：硬编码 LoadLibraryA 地址，成功！证明 DLL 加载流程正确
  • v9：IAT 寻址获取 LoadLibraryA，最终成功！不受 ASLR 影响

使用方法

  • 备份原游戏 exe（重命名为 BalladsOfHongye_original.exe）
  • 把 BalladsOfHongye_patched_v9_final.exe 复制到游戏 bin64，改名为 BalladsOfHongye.exe
  • 把 trainer_delayed.dll 放在游戏 bin64 目录（与 exe 同目录）
  • 通过 Steam 启动游戏，约 5 秒后修改器自动加载；按 F8/F9/F10 使用热键
