```
  +84px  div.dashboard-card              «✍️ 快速备忘»                      (w=320) clip=main.main[hidden]
  +84px  div.dashboard-card.stat-card    «0待办任务 0自媒体选题…»            (w=320) clip=main.main[hidden]
```

### 真机截图现象
侧边栏占约 150px 不折叠，内容区只剩约 180px；卡片被硬撑到 320px，右侧被 `main[hidden]` 裁掉：
- 「今天该干什么 · 2026-**」——日期被截断
- 「该管什么（到期优先 · **高优…**」——标题截断
- 右侧一列统计（「高优…」「去处理」按钮）完全不可见
- 底部出现横向滚动条

### 根因（三层叠加）
1. **栅格硬下限**：`.dashboard-grid { grid-template-columns: repeat(auto-fit, minmax(320px, 1fr)); }`
   —— `minmax` 的 320px 是硬下限，视口再窄也不会低于它
2. **侧栏不折叠**：900px 断点只把 `.sidebar` 压到 100px（`width:100px; min-width:100px`），
   **没有折叠成 60px 窄条**，继续吃掉 100px
3. **断点覆盖不全**：`styles.css` 共 1788 行，唯一的 `@media (max-width:900px)` 在**第 1739 行**就结束了，
   而其后新增的 `.hook-card` / `.triage-*` / `.hook-head` / `.quick-grid` 等样式
   （1751 行以后）**全部落在断点之外**，永远拿不到任何移动端覆盖

**算术**：360 − 100(sidebar) − 48(content padding ×2) = **212px 可用** < 320px 硬下限 → 溢出 84px

### 修复
- `styles.css` 追加两级断点（追加在文件末尾，靠层叠覆盖，不动既有桌面样式）：
  - `@media (max-width:900px)`：侧栏改**浮层抽屉**（`position:fixed` + `translateX(-100%)`），
    不再占用布局宽度；`.content` padding 收到 16px
  - `@media (max-width:640px)`：`.dashboard-grid` 改单列、`.stat-grid`/`.quick-grid` 改 2 列、
    `.profile-layout`/`.avatar-picker` 改 1/4 列、卡片 padding 收到 16px、
    顶栏标题加省略号、`.nav-item` 最小高度提到 44px
- `renderer/boot.js`：配合抽屉语义 —— `apply()` 同步维护 `body.sidebar-open`、
  窄屏首次进入默认收起、点击遮罩关闭抽屉；原有左边缘右滑展开手势保留

## 三、故障二：zonglan —— ☰ 菜单按钮被挤出屏幕

### 真机实测数据
```
[07-zonglan] vw=471 scale=1 docSW=471 over=0 clipped=0 small=3
```
**注意 `vw=471` 本身就是故障信号**：真机 CSS 视口应为 360，浏览器报告 471 ——
说明**页面内容过宽，把 layout viewport 撑大了**。

### 真机截图现象
顶部品牌区一路撑出屏幕，「鸿 woldvein 总览 项目工具链 ·」右侧的 **☰ 汉堡按钮完全不见**，
手机用户无法打开导航。

### 根因
- `.brand` 是 `display:flex` + `white-space:nowrap`，**不可压缩**
- 内部 `.brand-name` 26px 字号 + `letter-spacing:0.12em`，`.brand-sub` 12px + `letter-spacing:0.42em`
- 实测品牌区宽度 **399px** > 360px 视口 → 把 `.nav-toggle` 推到 right=490
- 原有媒体查询只有 `@media (min-width:1021px)`（管侧栏），**完全没有针对 header 的 max-width 断点**

### 修复
- `css/style.css` 的 `@media (max-width:860px)` 内补 header 规则：
  `.brand` 允许收缩（`flex:1 1 auto; min-width:0; overflow:hidden`）、
  文字容器保持与桌面一致的同行显示并用省略号截断、`.brand-mark` 缩到 34px、
  **`.nav-toggle { flex:0 0 auto }` 钉在右侧永不被挤出**
- 另加 `@media (max-width:480px)` 超窄屏断点：品牌名 16px、光斑 28px、按钮 20px

## 四、故障三：earth-online —— 「返回博客」按钮跑到屏幕外

### 真机实测数据
```
[08-earth] vw=374 scale=1 docSW=374 over=0 clipped=0 small=0
```

### 真机截图现象（最直观的铁证）
「← 返回博客」按钮被挤到**屏幕最右边缘**，文字「返回博客」四个字**竖排成一列**，
完全处于视口之外，360px 宽的屏幕上根本点不到。

### 根因（这个坑最有价值）
问题不在 earth-online 自己的 CSS，而在**共享样式表** `blog/projects/enhance.css` 第 44 行：

```css
body > * { position: relative !important; z-index: 1 !important; }
```

这条规则的意图是让内容盖在 body 的装饰光斑之上（z-index:1），
但 `position:relative !important` **连带劫持了子元素自己的 `position:fixed`**：
- `.back-to-blog` 的 `position:fixed` 被强制降级为 `relative`
- 它仍是 body 的 flex item，被 `justify-content:center` 推到右侧
- 再叠加 `left:14px` 相对错误基准偏移 → 最终 right=389（视口 360）

**放大效应**：body 是 `display:flex` 容器 —— `position:fixed` 元素**仍然参与 flex 布局的静态位置计算**，
这正是「明明写了 fixed 还是跑偏」的深层原因。

### 修复
- `blog/projects/enhance.css`：
  ```css
  body > * { z-index: 1; }
  body > *:not(.back-to-blog):not(.global-sun-btn) { position: relative; }
  ```
  只提升 z-index，**不再劫持 position**（保留原视觉意图，同时放行固定定位元素）
- `earth-online/index.html`：
  - `.back-to-blog` 补 `margin-right:auto` —— 让它在 flex 容器中的静态位置回到左上角
  - `#globalLoader::before` 的 600×600px 光斑改为 `min(600px, 100vw)`
  - `.loader-progress-wrap` 改为 `min(320px, 80vw)`
  - 新增 `@media (max-width:480px)`：`.wrap` padding 收到 24/16px、标题字号、按钮、
    loader 主题按钮尺寸、太阳按钮尺寸

> `enhance.css` 被 4 个页面共用（earth-online/index.html、earth-orbit-design.html、
> jizhiyun-pro/index.html、jizhiyun-demo/index.html），修一处全部受益。

## 七、生产主机网络故障诊断

### 现象
| 检查项 | 结果 |
|---|---|
| 云控制台实例状态 | 运行中（操作者确认） |
| ICMP ping（206.187.214.190） | ✅ 通，62ms，0% 丢包 |
| DNS 解析 lizyi.asia | ✅ 正常，唯一 A 记录 → 206.187.214.190 |
| TCP 22 / 80 / 443 / 2022 / 3000 / 3100 / 3101 / 8888 | ❌ 全部不通 |
| 扩展端口扫描（21/25/3306/3389/5900/6379/8080/10000 等 20 个） | ❌ 全部关闭 |
| 本机 curl https://lizyi.asia/ | ❌ 000 |
| 手机 Edge 打开 https://lizyi.asia/ | ❌ **ERR_CONNECTION_REFUSED** |
| 对照：baidu.com / gitee.com | ✅ 200（说明本机网络与互联网正常） |

### 关键区分（排除了「本机网络问题」和「代理问题」）
- 本机 SSH 2022 → **Connection timed out**（TCP 被 DROP）
- 手机 curl 直连 IP 443 → **0.07 秒立即失败**（TCP 收到 RST，被主动拒绝）
- 本机走代理 / 不走代理 → 都是 000
- 手机走 WiFi/移动数据 → 同样不通
- **baidu / gitee / github 均 200**

### 判断
主机内核与网络栈存活（ICMP 通），但**所有 TCP 服务端口的入站连接都不可用**。
这不是应用进程崩溃（那样至少 443 会有 Nginx 在监听、SMTP/DB 端口会开），
而是**云厂商安全组或主机防火墙层面把入站 TCP 整体拦掉了**。

### 需要操作者从云控制台做的事
1. 检查**安全组 / 网络 ACL** 规则，确认入站是否仍放行 443、2022（及 3100）
2. 检查主机内 `iptables` / `firewalld` / `ufw` 状态（可通过 VNC 控制台或云厂商的远程终端进入）
3. 进入后依次执行：
   ```bash
   pm2 list                          # 看 blog2.1 / blog-sentinel 是否 online
   pm2 restart blog2.1 --update-env
   pm2 restart blog-sentinel --update-env
   systemctl status nginx
   ss -lntp | grep -E ':443|:2022'   # 确认端口在监听
   iptables -L -n | head -50
   ```
4. 恢复后执行部署（脚本已就绪）：
   ```bash
   bash .workbuddy/real-device/auto-deploy.sh
   ```
   会自动：备份 → scp 五个文件 → md5 校验 → 健康检查

### 恢复后真机复验


### 踩坑备忘（下次直接照做）
1. **adb forward 会被 adb daemon 重启搞丢** —— 一条 bash 命令里只能调一次 adb，
   或把 forward 建立放进 Node 进程内部（`edge-drive.js` 的 `ensureForward()`）
2. **Node 的 `fetch` 连 127.0.0.1 会失败**（走代理/IPv6）—— 改用 `http.get` + `agent:false`
3. **移动模式下 `innerWidth` 会被内容撑大**，不能用它当基准（自我指涉，永远抓不到元凶）。
   要用 `mobile:false` + `Emulation.setDeviceMetricsOverride` 得到真实宽度
4. **`Input.insertText` 比逐字符 `keyDown/keyUp` 可靠**，`type=password` 尤其如此
5. **`execSync().toString()` 会破坏 PNG 二进制** —— 用 `execFileSync` + `encoding:undefined` 拿 Buffer
6. **滑块验证码要发完整事件链**：`mousePressed` → `mouseMoved`×N → `mouseReleased`
