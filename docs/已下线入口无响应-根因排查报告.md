# 已下线功能入口点击无响应 —— 根因排查报告

> 排查日期：2026-11-11　｜　范围：主站 `qrcode-login/` + 静态页面 + `blog-sentinel/` 后台
> 方法：静态代码交叉比对 → 中间件级实机复现 → 公网 curl → 浏览器 CDP 真机点击（走系统代理 + 真实证书）
> 结论一句话：**「⚡ 无法连接服务？点此直接进入博客」访客直通入口的能力早已被安全整改事实下线，但入口仍无条件渲染；点击后是静默 `302` 回环，零提示、零报错、零状态变化，用户感知就是"点了没反应"。**

## 2. 功能识别：为什么锁定 `guestEnter`

### 2.1 全站入口盘点结果

静态交叉比对结论：**所有 HTML 事件入口都有对应函数定义**（`preventDefault`/`stopPropagation` 是 `event.xxx()` 的误报），**所有前端 `/api` 调用都有后端路由**（`/api/projects/scan`、`/api/projects/import` 在 `modules/projects/routes.js:33,39` 注册并挂载于 `/api/projects`）。

> 结论：不存在"事件入口找不到 handler"或"调用了已删除接口"的孤儿入口。问题不在"入口与代码失联"，而在**入口与功能可用性失联**。

### 2.2 候选功能逐一排除

| 候选 | 是否"已下线" | 点击是否有反馈 | 是否目标 |
| --- | --- | --- | --- |
| 「⚡ 无法连接服务？点此直接进入博客」`guestEnter()` | ✅ 事实下线 | ❌ **完全无反馈** | ✅ **是** |
| 「🔓 直接登录（个人免密）」`directLogin()` | ⚠️ 受 `DIRECT_LOGIN_IPS` 白名单限制（非白名单 403） | ✅ `try/catch` + `alert` + 按钮状态复位（`index.html:720-742`） | ❌ 有明确反馈 |
| 扫码登录 tab | ❌ 用户明确要求保留，接口齐全 | ✅ `initQr()` 有状态文案 | ❌ 未下线 |
| 立即注册 | ⚠️ `ALLOW_REGISTER=false` 可关闭 | ✅ 后端 403「本站暂未开放注册」（`routes.js:255`） | ❌ 有明确反馈 |
| `blog-sentinel` 后台 8 个视图 | ❌ 全部有 loader + 后端接口 | ✅ | ❌ 无孤儿入口 |

### 2.3 `guestEnter` "事实下线"的证据链

1. **前端行为**：`guestEnter()` 写 `web_guest=1; path=/; max-age=604800`，然后 `location.href = "blog/index.html"`（`index.html:707-710`）。
2. **后端不认这个 cookie**：`getTokenFromReq()` 只从 `web_token` Cookie 和 `Authorization: Bearer` 取令牌（`middleware/auth.js:34-40`），**全文件无 `web_guest`**。
3. **历史证明从未实现**：`git log -S "web_guest" --all` 仅返回 `095f8de`（2026-09-08 引入 `index.html`）；`git grep web_guest $(git rev-list --all)` 在排除 `index.html`/`projects.html` 后**为空** —— 可追溯历史中后端从未有过 `web_guest` 鉴权逻辑。（`projects.html:389`、`index.html:1010` 退出登录时还会清除它，是典型的"僵尸 cookie"残留。）
4. **安全整改固化了失效表现**：`7e5e3e3`（2026-11-10，N-08）用 `createBlogStatic` 替代 `express.static`，`/blog/*` 全量鉴权；未登录页面请求统一 `302` 回 `/`（`blogStatic.js:154-158, 211-219`），`authGate` 对非 API 路径同样 `res.redirect("/")`（`auth.js:55`）。

> 观察与推断分离：**观察** = `web_guest` 在可追溯历史中后端零消费、当前 100% 走 302 回环；**推断** = 该入口是自设计起就未真正连通，或早期逻辑已随历史被裁剪。历史可能不完整（仓库始于 `763dc49`），但**当前行为与"功能已下线"完全一致**，不影响结论。

## 4. 根因清单（按可能性从高到低）

### 根因 1 —— 入口渲染与功能下线状态脱钩 + 失败路径静默回环 【100% · 已确认 · 直接根因】

- **判断依据**：入口 HTML 无条件存在且高亮可点；点击后 `web_guest=1` 写入但后端解析 token 为 `""`；`/blog/index.html` 与 `/projects.html` 均返回 `302 Location: /`；`directLogin()` 同类场景有 `alert`，唯独它没有。
- **验证方法**：
  - 中间件实机：`getTokenFromReq({cookie:"web_guest=1"})` → `""`；`createBlogStatic` → `302 /`；`createAuthGate` → `302 /`；对照组带有效 `web_token` → `next()` 放行。
  - 公网：`curl -o /dev/null -w "%{http_code} %{redirect_url}" -H "Cookie: web_guest=1" https://lizyi.asia/blog/index.html` → `302 https://lizyi.asia/`；`/health` → `200`。
  - 浏览器 CDP：点击后 `url` 仍为 `https://lizyi.asia/`、`loginBoxVisible:true`、`visibleErrors:[]`、`webGuestCookie:"1"`、`hasWebToken:false`。
- **修复建议**：见 §6 方案 A/B —— 隐藏入口或改为明确的"已下线"提示，禁止让它看起来可用。
- **修复后验证点**：① 页面不再出现该可点入口；② 即使残留，点击后有可见文案且**不再产生 302 导航回环**；③ `document.cookie` 不再被写入 `web_guest`。
- **预期 vs 实际不一致**：预期"功能下线 → 入口消失/禁用/提示"；实际"功能下线 → 入口照常高亮 → 点击静默回原点"。

### 根因 2 —— 缺少 feature flag 机制，下线状态无法传递到前端入口 【90% · 系统性根因】

- **判断依据**：`core/config.js` 无任何业务功能开关；`bootstrap.system` 虽下发 `geoip.enabled` / `map.offline` / `members.enabled`，但 `app.js` 只在 `loadSystem()` 里把它们渲染成状态文字（`app.js:618-620`），**没有任何一处据此控制 `data-view` 导航项的显隐** —— `index.html:47-54` 的 8 个 nav-item 全部硬编码无条件渲染。
- **验证方法**：把 `INGEST_KEY` 置空（members 未启用）后，观察 `data-view="members"` 入口是否消失 —— 实测不会消失，仅在进入视图后由 `loadMembers()` 显示"成员快照未启用"文案（`app.js:502`），属于**数据层提示，非入口层下线**。
- **修复建议**：建立 `capabilities` 字段随 `bootstrap` 下发，前端统一在渲染导航时按 `enabled` 决定 `hidden`/`disabled`/`title="已下线"`；入口与 loader 双注册，避免只删一半。
- **修复后验证点**：关闭任一 capability → 对应入口 DOM 消失或带 `disabled` + 下线说明；开启 → 恢复；`app.js` 中所有 `data-view` 均在 capability 表中有登记。
- **预期 vs 实际不一致**：预期"下线开关 → 前端入口同步收敛"；实际"开关只下发、不被入口消费；真正下线的 `guestEnter` 连开关都没有"。

### 根因 3 —— 路由守卫的 302 安全重定向吞掉了失败反馈 【80% · 机制性根因】

- **判断依据**：N-08（commit `7e5e3e3`）把未登录页面请求从 `200 + 登录页实体` 统一改为 `302 /`（`blogStatic.js:145-158` 注释与实现），目的是"不再能靠 200/404 测绘目录树"。该安全设计正确，但副作用是：**任何指向受保护页面的失效入口，其失败都会变成一次无声的浏览器跟随跳转**，URL 回到原点，页面看起来毫无变化。
- **验证方法**：CDP 抓到的响应里只有 `/api/me` 401（预期的未登录探测）和 `favicon.ico` 404，**无 guest 相关错误**；`visibleErrors:[]`；控制台零异常 —— 因为 302 不是错误。
- **修复建议**：守卫层与前端约定"下线入口"专用反馈：要么前端在点击前就地判定并提示（推荐，见 §6），要么后端对带标记的下线请求返回 `410 Gone` + 可读文案，让 `api()` 能捕获并 `toast`。
- **修复后验证点**：点击下线入口 → 有 `410`/明确文案或前端 toast；Network 中不再出现静默 `302 → /` 的导航回环。
- **预期 vs 实际不一致**：预期"访问被拒 → 告知原因"；实际"访问被拒 → 静默回首页，用户以为按钮坏了"。

### 根因 4 —— "僵尸 cookie"：前端写、后端从不读，设计意图与实现脱节 【60% · 历史根源】

- **判断依据**：`web_guest` 仅出现在 `index.html:708,1010` 和 `projects.html:389`（写与清），后端与 Nginx 配置零出现；按钮文案"无法启动后台服务时，跳过登录直接进入博客"描述的是一种**纯静态兜底能力**，但在服务端接管的架构下（`server.js:227-231` 的 `createBlogStatic`）根本不存在"绕过后端直出博客"的路径。
- **验证方法**：`git log -S "web_guest" --all` 与 `git grep web_guest $(git rev-list --all)`（排除前端两文件）→ 后端零命中。
- **修复建议**：删除 `guestEnter()` 函数、`web_guest` 的写入与清除逻辑（`index.html:708,1010`、`projects.html:389`），彻底清理残留语义。
- **修复后验证点**：全仓 `grep web_guest` 零命中（或仅存于变更说明）。
- **预期 vs 实际不一致**：预期"cookie 是某条鉴权路径的凭据"；实际"它是没有任何消费者的历史残留"。

### 根因 5 —— 事件绑定 / 点击处理未执行 【0% · 已排除】

- **排除依据**：CDP 点击后 `webGuestCookie="1"`，直接证明 `guestEnter()` 第一行已执行。事件委托、handler 均正常。
- **验证方法**：同 §2.3 浏览器复现；对比 `document.cookie` 前后差异。
- **结论**：非事件层问题，无需修复。

### 根因 6 —— 相关接口调用失败 / 被拦截 / 异常处理吞错 【0% · 已排除】

- **排除依据**：`guestEnter()` 是 `cookie + location.href` 的**页面导航**，不发起任何 `/api` 请求，因此"接口是否仍被调用"不适用；失败发生在导航层（302），进不了 `api()` 的错误分支；`try/catch` 也抓不到 302（它不是异常）。所谓"吞错"是**语义层的失败被当成成功的导航**，不是代码层面的异常吞噬。
- **验证方法**：CDP Network 记录中无 guest 触发的 `/api` 调用；控制台仅 `/api/me` 401 与 favicon 404。
- **结论**：非接口层问题；修复重点是消除导航回环本身（§6）。

### 根因 7 —— 浏览器缓存 / 静态资源版本导致新旧前端混用 【0% · 已排除】

- **排除依据**：该入口是**内联在 `/index.html` 里的 HTML + 内联脚本**，不经过 `?v=N` 版本化的外部 JS；`curl https://lizyi.asia/` 明确抓到 `guestEnter()` ×2、按钮文案 ×1，说明用户拿到的就是含该入口的最新页面；CDP 全新 user-data-dir（零缓存）同样复现。
- **验证方法**：`curl -s https://lizyi.asia/ | grep -c "无法连接服务？点此直接进入博客"` → `1`。
- **结论**：与历史"地图看不到"的外部脚本 `max-age` 缓存问题性质不同，本次与缓存无关。

### 方案 C —— 建立 capability 机制（治本，防复发）
